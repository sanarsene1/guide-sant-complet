- The VetoCare site is static HTML/JS in ``; `/` redirects there. Content lives in `data/*.js` (`const X=[...]`), so edit data, not page markup, to change animals/diseases/quiz. Why: pages render everything from these arrays.
- Species category keys, labels (`CAT`) and display order (`ORD`, `byOrd`) are defined once in `assets/app.js`; every page sorts its species lists with `byOrd`. `src/test/rdc-animals.test.ts` guards that the priority animals exist everywhere.
- Site nav is duplicated in every `*.html`; the mobile bottom tabs are built from it in `app.js`, skipping links with `data-p` or `data-about`. Why: À propos lives only in the header/hamburger (hover card on desktop, anchored `left` since it sits 2nd after Accueil), never in the 5 tabs. It is not in the footer nor in any home-page section; on phones it opens `a-propos.html`.
- In the nav, `data-mob="tab"` marks a link that must stay in the 5 bottom tabs but be hidden in the phone hamburger panel (Animaux); `data-mob="menu"` marks a link shown in the header/hamburger only and never in the tabs (the account link, `Mon compte` → `/espace-veterinaire`). Both are handled by the `@media(max-width:900px)` rules in `assets/style.css` + `assets/home.css` and the tab filter in `app.js`. Why: one nav markup feeds desktop bar, hamburger panel and bottom tabs.
- `.vnote` (Avis important) text is animated by `app.js` as a looping typewriter; keep its copy in `.vnote-t`/`.vnote-s` markup. Why: the script reads those paragraphs and keeps a single readable copy (a transparent ghost that reserves height and serves selection/screen readers) under an `aria-hidden`, unselectable animated copy; never add a second readable copy or the text is copied/read twice.
- On the home page the `.vnote` is a direct child of `section.care` (after `.care-copy`), not inside `.care-copy`; `home.css` gives `.home .care>.vnote` `grid-column:1/-1` plus centered content. Why: it must sit as a full-width centered row below the photo and the engagement column, on every screen size.
- The footer (`footer.ft`) is identical markup in every `*.html` and is styled only at the end of `assets/style.css` with its own `--ft-*` tokens; it uses a `div[role=navigation]`, never `<nav>`. Why: half the pages don't load `home.css`, and `style.css` hides bare `nav` elements on mobile.
- `animaux.html` uses the home shell (`body.home`, vban + new header, `home.css`) plus its own `assets/animaux.css` (`.an-*`, `--home-*` tokens only); each species sheet links to its diseases/advice/quiz via `N2C` (species name → category key) and `?c=` / `?sp=` / `?a=` query params. Why: one design language across redesigned pages, and the sheet is the hub to the other sections.
- `conseils.html` uses the same home shell as `animaux.html` plus `assets/conseils.css` (`.cs-*`, `--home-*` tokens only). Advice lives in `data/conseils.js` as `{c,th,t,r,g[],a}` with theme labels in `THEMES`; species photos are `assets/img/conseils/<cat>.webp`. The page reads `?c=` (species), `?t=` (theme) and `?k=` (open advice). Why: other pages deep-link with `conseils.html?c=`, and the page renders filters and cards from this data.
- `maladies.html` uses the home shell plus `conseils.css` and `maladies.css` (`.ml-*`). Each `MAL` entry in `data/maladies.js` is `{t,c,a,s,ty,g,r,f[],p[],ct,z,v,o}` (field meanings in the file header); `s` is a comma-separated sign list split into chips, so a sign never contains a comma. No treatment/drug fields. Why: the page builds cause filters, severity, search and the detail dialog from these fields; `src/test/maladies-data.test.ts` guards them.
- `assets/quiz.js` queues finished quizzes in `localStorage['vc-quiz-pending']` when `vc-account` holds the visitor id, then posts them to `/api/quiz-sync` with the visitor's own token; `/mon-compte` uploads leftovers. Why: goals count quizzes right away; the static site has no auth client.
- Legal pages (`politique-confidentialite.html`, `mentions-legales.html`, `conditions.html`) are static pages in `public/site/` built on the À propos shell with `.lg-*` styles in `home.css`; their links sit in every `footer.ft .ft-legal`, and React pages render `LegalLinks` from `src/components/legal/legal-links.tsx`. Shared legal copy (link list, educational notice, brevet disclaimer) lives only in `src/lib/legal.ts`, guarded by `src/test/legal-pages.test.ts`. Why: one source for the wording on the site, the account and the PDFs.
